# 実装タスク（Data Management Documentation）

本タスク群は、要件と設計に基づき、既存データ管理機能の体系的ドキュメント整備を完了させるための実行計画である。優先度高 → 低の順で記載。

## 1. スキーマ定義とモデル同期

- [ ] Firestore コレクション/フィールド一覧を作成（型/必須・任意/既定値）
- [ ] Freezed モデルの整合確認と不足モデルの追加（`fromJson/toJson` 含む）
- [ ] スキーマ版管理ポリシー（バージョンフィールド/履歴表）の追記

## 2. Repository/DataSource 契約整理

- [ ] 既存 Repository の公開メソッド一覧化（入出力型、Stream/Future 区分）
- [ ] DataSource ごとのクエリ/書込パターンを表形式で追加
- [ ] 事前条件/事後条件/不変条件の明記（主要メソッド）

## 3. クエリ戦略とインデックス

- [ ] 画面別クエリ要件（条件/並び替え/limit/ページング）を整理
- [ ] `firestore.indexes.json` と対応関係の表を追加
- [ ] コスト最小化ガイド（select 的取得、limit、カーソル）を記述

## 4. リアルタイム・一貫性・同時実行

- [ ] Stream 提供箇所のリスト化（重複状態除去ポリシー）
- [ ] 競合時ルール（トランザクション/サーバタイムスタンプ/楽観制御）を明記
- [ ] オフライン時の整合と再接続挙動の説明

## 5. セキュリティ整合

- [ ] Repository 事前条件と Firestore ルールの対応表を作成
- [ ] サーバ専用処理（Functions/Admin）範囲を明確化
- [ ] PII 範囲と最小権限・過剰取得防止の指針を追記

## 6. エラーハンドリングと可観測性

- [ ] FirebaseException → AppException マッピング表（コード/カテゴリ）
- [ ] 再試行/フォールバック/ユーザー通知方針を整理
- [ ] 監視ポイント（ログ/メトリクス/アラート）を設計にリンク

## 7. 性能/コストガバナンス

- [ ] 目標 p50/上限読取/書込/費用の指標を明記
- [ ] 高頻度更新のデバウンス/バッチ利用の推奨を反映
- [ ] 集計の事前計算/Functions 集約の適用基準を追記

## 8. 移行とバックフィル

- [ ] 段階移行フロー（二重読取/新形式書込）の手順書
- [ ] バックフィル実行手順（エミュレータ/本番）とロールバック条件
- [ ] レート制限/ホットパーティション回避の運用ノート

## 9. テスト戦略

- [ ] Repository 単体テスト観点（成功/失敗、例外マッピング）
- [ ] インデックス前提クエリの統合テスト観点
- [ ] 移行シナリオの冪等性検証観点
- [ ] CI での Firestore emulator 実行手順

## 10. ドキュメント公開/メンテ

- [ ] docs/ 目次へのリンクと参照関係を追加
- [ ] 変更時の更新手順（誰が/いつ/どこを）
- [ ] 保守責任者/レビュー体制の明記
